# Validation status and limitations

This is a runnable validation build, not a certified production replacement for STAAD.Pro. Six supplied reference outputs contain envelopes, not complete member/nodal databases. Five can be evaluated; Sample 7 has a loaded mechanism and its reference remains unverified. See VALIDATION_RESULTS.md and validation/comparison.json for every checked quantity.

1. True moment extrema differ from some reference envelopes. Samples 1 and 2 reproduce the reported moments when evaluated at the reference stations, but have higher analytical extrema between those stations. Results are not reduced to imitate a reference number.
2. Fully unitized span displacements retain differences of approximately 0.064-0.129 mm (0.12-0.15%). These exceed the initial tolerance. Global and mullion entries duplicate the same discrepancy; production interchangeability remains unproven.
3. Explicit AY/AZ are preferred. With YD and ZD but no shear areas, the engine assumes Cowper's rectangular correction 10(1+nu)/(12+11nu) times AX. This is an engineering approximation for arbitrary hollow aluminium extrusions. Supply independently established effective shear areas for design work.
4. Raw solver displacements and the v0.2 `physical_response` include Timoshenko shear and continuous extrema. The original `properties`/`casement` compatibility fields retain the original interior sample stations, endpoint translation/rotation interpolation and an Euler-Bernoulli fixed-end load bubble. This resembles the reference's section recovery, but does not establish exact OpenSTAAD equivalence. The interface labels these distinct result definitions and defaults to physical response; profile tables retain legacy semantics.
5. FLOOR LOAD accepts complete rectangular faces only; slopes, nonrectangular regions and clipped panels fail. It does not emulate all STAAD load-generator options.
6. Sample 5 has no reference output. No licensed live OpenSTAAD oracle was run. Analytical checks and equilibrium supplement, but cannot replace, member-level reference validation.
7. In-house station distances are metres; reference distances are inches. End-force station 0/1 is an end identifier. Legacy casement blocks lack station_unit; use units.staad_detected.length. The staad_detected field truthfully describes the adapter's N/METER source, not a running STAAD instance.
8. Linear small-displacement analysis only: no design capacity, code compliance, buckling, shell, solid, nonlinear or dynamic checks. Mechanisms and ill-conditioning fail. Only completely disconnected, unloaded rotational DOFs are omitted, with diagnostics.
9. Job storage remains in memory. Use one API process. Restarting loses job records. The launcher binds to localhost. Authentication, durable storage and deployment hardening are outside this supplied replacement task.
10. In-house recovery errors fail rather than producing zero forces or silently switching backend. Legacy OpenSTAAD behavior is retained separately. Bentley processes are never touched by the in-house path.
11. Original Sample 7 has no vertical load path through members 5, 16, 27 and 38 and remains unchanged and rejected. The user-approved separate revision removes those four start FX releases and solves all six cases with unchanged supports. It has no independent reference result; its 121.329 mm absolute movement and 50.827 mm chord-relative movement require project-specific serviceability and linear-model applicability checks. CMOM is supported and independently tested. See SAMPLE_6_7_VALIDATION.md. Sample 6's damaged reference is separately normalized without changing its numbers.
